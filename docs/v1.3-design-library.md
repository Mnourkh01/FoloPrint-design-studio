## 2. Proposed API: `GET /designs`

### Why a new list DTO instead of reusing `DesignProjectDto`

`DesignProjectDto` carries the full design document (`design.placements[].objects[]`
with every coordinate). A library page only needs counts and metadata; shipping full
documents for up to 50 designs per page is wasted payload and invites the client to
treat list data as editable state. The list item is a deliberate summary.

### Shared types (packages/shared/src/types.ts)

```ts
/** Per-area summary for the design library; no object geometry. */
export interface DesignPlacementSummaryDto {
  printAreaKey: string;
  /** Human name resolved from the template's print area, falls back to the key. */
  printAreaName: string;
  objectCount: number;
}

/** One row in the design library. Deliberately excludes the design document. */
export interface DesignListItemDto {
  id: string;
  template: {
    id: string;
    name: string;
    slug: string;
  };
  /** Ordered by the template's area sortOrder (front before back). */
  placements: DesignPlacementSummaryDto[];
  /** Same shape and ordering as DesignProjectDto.previews; empty until rendered. */
  previews: DesignPreviewDto[];
  createdAt: string;
  updatedAt: string;
}

export interface DesignListDto {
  items: DesignListItemDto[];
  page: number;
  pageSize: number;
  totalItems: number;
  totalPages: number;
}
```

Path-safety rules carried over from v1.2: `previewUrl` is a relative API route,
never a storage path. `storagePath` / `previewPaths` / absolute filesystem paths
never appear anywhere in the response.

### Controller / service changes

- `DesignsController`: add `@Get() list(@Query() query: ListDesignsQueryDto)`.
  No route conflict: Nest matches the exact `/designs` path before `/designs/:id`,
  and `:id` is guarded by `ParseUUIDPipe` anyway.
- `DesignsService.list(page, pageSize)`:
  - `findMany` ordered by `updatedAt: 'desc'`, with `skip`/`take`, including
    `productTemplate` + `printAreas` (same include shape used everywhere else).
  - `count()` for totals, both inside one `prisma.$transaction([...])` so page
    math is consistent.
  - Placement summaries come from `normalizeDesignDocument(designJson)`; counts
    are computed per placement, then sorted by the template's `sortOrder` (reuse
    the ordering logic in `toPreviewDtos`).
  - **Corrupt-row policy**: `findById`/`render` treat an unreadable document as a
    500 because the caller asked for that one design. The list must not let one
    corrupt row take down the whole library. A row whose document fails to
    normalize is returned with `placements: []` (previews and metadata still
    shown) and the error is logged server-side. Tradeoff documented here so it is
    a decision, not an accident.

### Query DTO (`ListDesignsQueryDto`)

```ts
class ListDesignsQueryDto {
  // page: integer string, default 1, clamped to >= 1
  // pageSize: integer string, default 20, clamped to 1..50
}
```

- `class-transformer` `@Transform` parses and **clamps**; `@IsInt` rejects
  garbage (`page=abc` → 400) after transform.
- Clamping (not rejecting) out-of-range numbers is the requested behavior:
  `pageSize=500` → treated as 50, `page=0` → treated as 1. A `page` beyond the
  last page returns an empty `items` array with correct totals (normal REST
  behavior, simplest for clients).
- Existing global `ValidationPipe` (`whitelist + forbidNonWhitelisted + transform`)
  applies; unknown query params are rejected, consistent with the rest of the API.

`PAGE_SIZE_MAX = 50` and `PAGE_SIZE_DEFAULT = 20` live as constants next to the DTO.

## 3. Pagination behavior

- Offset pagination (`skip`/`take`). Cursor pagination is over-engineering at this
  scale (single-user POC, no auth, no concurrent writers); revisit only if the
  library grows past thousands of rows.
- Sort: `updatedAt DESC`. Prisma orders by the single column; ties (bulk-seeded
  rows sharing a timestamp) get `id DESC` as a deterministic tiebreaker so
  pagination never duplicates/skips rows across pages.
- Defaults: `page=1`, `pageSize=20`. Max `pageSize=50` (clamped, not rejected).
- Response always echoes the **effective** page/pageSize after clamping so the
  client renders pagination from truth, not from what it asked for.

## 4. Web UI plan (`/designs`)

### Layout

Card grid (matches the home page's template-card language, not a new design system):

```

│ Design Library                          [n saved designs]│
│ Saved designs, newest first.                             │
│                                                          │
│ ┌────────────┐  ┌────────────┐  ┌────────────┐          │

│                                                          │

└──────────────────────────────────────────────────────────┘
```

Per card:

- **Thumbnail**: first preview in `previews` (template area order means front
  wins when present). When two previews exist, front large + back small, or a
  simple two-up strip; decided at implementation against the existing CSS.
  Image URL gets the same `?t=<renderedAt>` cache-buster used on the preview page.
- **Template name** (human), slug as secondary text.
- **Placement chips**: `Front · 2 objects`, `Back · 1 object` from
  `placements[]`.
- **Updated**: relative-ish display via `toLocaleString()` (consistent with the
  preview page; no new date library).
- **Actions**: `View` → `/designs/{id}`; `Edit` → `/editor/{slug}?design={id}`
  (both routes already exist).

### Pagination UI

control for it in v1.3.

## 5. Empty and missing-preview states

| State | Detection | UI |
|---|---|---|
| No designs at all | `totalItems === 0` | Headline "No saved designs yet." + body "Open a template, place your artwork, and save. Your designs will show up here." + CTA button to `/` (template list). Mirrors the home page's notice pattern. |
| API down | fetch throws | Same `notice` pattern as home page: "API is not reachable" + start commands. |
| Design never rendered / edited since last render | `previews.length === 0` | Placeholder block in the thumbnail slot: "No preview rendered" + hint "Open the design and generate mockups." The server already deletes previews on update, so `previews` is empty exactly when nothing current exists; there is no separate "stale" state to detect. |
| Partial previews (front rendered, back placement added later... impossible today) | n/a | Not possible: render always renders every placement and update clears all previews. Whatever `previews` contains is current. No special handling. |
| Page beyond last | `items.length === 0 && totalItems > 0` | "Nothing on this page." + link back to page 1. |

Note on "stale": since v1.2, `update()` clears `previewPaths` and `render()`
rewrites all of them, so a persisted preview can never be stale relative to the
document. "Missing" is the only degraded state, and the UI says so plainly.

## 6. Tests

### API e2e (`apps/api/test/app.e2e-spec.ts`, new `GET /designs` describe block)

Block starts by deleting all `design_projects` rows (test DB only; suite already
owns the DB) so list assertions are deterministic, then seeds a known set through
the public API (no direct Prisma inserts for fixtures, consistent with the suite).

1. **Empty list**: after wipe, `GET /designs` → 200, `items: []`, `totalItems: 0`,
   `totalPages: 0`, `page: 1`.
2. **Newest first**: create design A, then B, then update A → order is [A, B]
   (update bumps `updatedAt`).
3. **Pagination**: create 5 designs, `pageSize=2` → page 1 has 2, page 2 has 2,
   page 3 has 1; `totalItems: 5`, `totalPages: 3`; no row appears twice across
   pages.
4. **pageSize clamp**: `pageSize=500` → response `pageSize: 50`; `pageSize=0` →
   `pageSize: 1` (clamped, not 400). `page=0` → `page: 1`.
5. **Garbage params**: `page=abc` → 400; unknown param `foo=1` → 400
   (forbidNonWhitelisted).
6. **Template info**: items carry `template.id/name/slug` matching the seed.
7. **Preview metadata**: render a design with front+back placements → its list
   item has two `previews` entries with relative `previewUrl` and ISO
   `renderedAt`, ordered front before back.
8. **No path leakage**: `JSON.stringify(body)` contains no `storagePath`, no
   `previewPaths`, no `previews/` storage prefix, no drive-letter or backslash
   path, no `STORAGE_ROOT` segment. (Same leak assertions style v1.2 used.)
9. **Summary correctness**: item `placements` reports the right
   `printAreaKey`/`objectCount` per area and does NOT contain a `design` document
   or object coordinates.

### Playwright (`apps/web/e2e/design-library.spec.ts`, new file)

One journey, reusing helpers/patterns from `editor-smoke.spec.ts`:

1. Open editor for `classic-tee`, upload asset, place object, save → note design id.
2. Render previews from the preview page.
3. Navigate to `/designs` via the new topbar link.
4. Assert the design's card is visible: template name, placement chip, preview
   `<img>` that actually loads (naturalWidth > 0).
5. Card `View` → lands on `/designs/{id}` with previews visible.
6. Back to library, card `Edit` → editor loads with the design (existing
   `?design=` flow), canvas shows the object.
7. Empty state: with a wiped DB this is racy against the seed of step 1, so the
   empty-state assertion runs FIRST in the spec (before any design is created),
   or in a serial `describe` ordered before the journey. Decided at
   implementation; goal is no inter-test dependence on execution order.

## 8. Risks

1. **One corrupt designJson row 500s the whole list.** Mitigated by the per-row
   degrade policy (section 2). Without it, the library page would be the single
   most fragile page in the app.
2. **e2e determinism**: the new block wipes `design_projects`, which could break
   existing blocks if they run after and assume earlier designs exist. Audit of
   current suite says blocks create their own fixtures, but this is verified
   during implementation, and the wipe is scoped to the new block's `beforeAll`.
3. **Playwright empty-state vs journey ordering** (section 6, point 7). Solved by
   running the empty assertion before any design is created in that spec, plus
   web tests run against a freshly seeded DB per the existing npm script contract.
4. **Topbar change touches every page**, including the editor smoke test's DOM.
   Low risk; verified by running the existing spec unchanged.
5. **JSON parsing per row** (`normalizeDesignDocument` × pageSize) is O(50) tiny
   documents per request — negligible now; flagged for the future if documents
   grow large (select only needed columns then).
6. **Offset pagination drift** when a design is updated between page views (a row
   can jump to page 1 and reappear). Accepted: single-user POC; noted for later.
7. **Scope creep magnets**: delete, search, filters, bulk ops, thumbnails as
   stored files. All explicitly out of scope for v1.3.

## Implementation results (2026-06-06)

### Deviations from the plan

1. **Global throttle made env-overridable.** `app.module.ts` had a hardcoded
   120 req/min global ThrottlerGuard limit; the e2e suite (39 tests) exceeds it.
   Changed to `GLOBAL_THROTTLE_LIMIT ?? 120` following the existing
   `UPLOAD_THROTTLE_LIMIT`/`RENDER_THROTTLE_LIMIT` pattern; `jest-setup.ts` sets
   it to 10000 for tests. Production default unchanged.
2. **Playwright `workers: 1`.** The design-library spec wipes `design_projects`
   (via `prisma db execute` from the API workspace) to prove the empty state;
   one worker guarantees the wipe never races the editor smoke spec mid-flow.
   Suite is 4 tests; the serialization cost is negligible.
3. **e2e block uses `beforeEach` wipe** (not `beforeAll`), making every list
   test own the whole table. Deterministic and order-independent within the block.
4. **Print area names** are seeded as "Front print"/"Back print" (not
   "Front"/"Back" as the plan's examples assumed); tests assert against the
   seeded template, not hardcoded names.
5. **Single-preview thumbnails** use `object-fit: contain` (two-up strips use
   `cover`) — a lone square preview in a wide strip cropped too aggressively.
   Found during browser verification.

### Final API shape

Exactly as planned (section 2): `GET /designs?page&pageSize`, clamped pagination
(default 20, max 50), `updatedAt DESC, id DESC`, `DesignListDto` envelope with
`DesignListItemDto` summaries. No design document, no storage paths, relative
preview URLs only. Corrupt rows degrade to `placements: []` with a server-side
warning logging only the design id and error message.

### UI behavior

- `/designs`: card grid, two-up (or single) preview thumbnails with
  cache-busted URLs, "No preview rendered" placeholder, template name,
  updated timestamp, per-area chips (`Front print · 1 object`), View/Edit
  actions, prev/next pagination (`?page=N`), empty state with CTA to
  `/editor/classic-tee`, API-down notice.
- Topbar "Design Library" link on every page (`layout.tsx`).
- "All designs" link on the design preview page.
- Verified in a real browser at 1440px: library grid, thumbnails, chips,
  preview page links. Console clean except the pre-existing favicon 404.

### Limitations

- Offset pagination can drift when a design is updated between page views
  (acceptable single-user POC; cursor pagination deferred).
- `pageSize` is fixed at the server default in the UI; no page-size control.
- No delete/search/filter (out of scope, see above).
- Thumbnails stream full-size preview PNGs (canvas-sized); dedicated thumbnail
  files are a future optimization if templates grow.
