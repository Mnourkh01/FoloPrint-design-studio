# v1.5 — Text Objects

Status: **implemented** (see "Implementation results" at the end)
Branch: `feature/v1.5-text-objects` (from `staging` @ `246f618`)

Goal: users can add editable text to print areas, and the text renders consistently in the
Fabric editor and in the server-side sharp mockups.

---

## 1. Contract change — discriminated union on `DesignObject`

### Current shape (v2 document, image-only)

```ts
interface DesignObject {
  assetId: string;
  x: number;       // center, canvas px
  y: number;       // center, canvas px
  width: number;   // canvas px, before rotation
  height: number;  // canvas px, before rotation
  rotation: number; // degrees clockwise
}
```

### Proposed shape

```ts
/** Geometry shared by every object kind. Same semantics as today. */
interface DesignObjectBase {
  x: number;        // center, canvas px
  y: number;        // center, canvas px
  width: number;    // canvas px, before rotation
  height: number;   // canvas px, before rotation
  rotation: number; // degrees clockwise around the center
}

interface ImageDesignObject extends DesignObjectBase {
  type: 'image';
  assetId: string;
}

interface TextDesignObject extends DesignObjectBase {
  type: 'text';
  /** Plain text. `\n` allowed for explicit line breaks. No markup ever. */
  text: string;
  /** Key into the shared font whitelist (e.g. "inter", "oswald"). NOT a free string. */
  fontFamily: FontFamilyKey;
  /** Canvas px (uniform scaling is baked into this value on save, see §3). */
  fontSize: number;
  /** Strict #RRGGBB. No alpha, no named colors, no CSS functions. */
  color: string;
  align: 'left' | 'center' | 'right';
}

type DesignObject = ImageDesignObject | TextDesignObject;
```

### Document version: stay at v2, normalize objects at read time

No bump to v3. The change is additive: a missing `type` on a stored object means
`'image'` (every existing object has `assetId`). `normalizeDesignDocument` gains one more
normalization step:

- v1 doc → v2 doc (existing behavior)
- any object without `type` → `{ type: 'image', ...object }`

Every save writes `type` explicitly, so documents self-upgrade on the next save exactly like
v1 → v2 does today. Existing image-only designs keep working with zero migration.

Why not v3: a version bump signals a structural change readers cannot interpret without new
code. Old readers that ignore `type` still read image objects correctly (assetId untouched),
so this is a compatible extension, not a new structure.

### Width/height semantics for text

`width`/`height` of a text object = the measured bounding box of the laid-out text in canvas
px, as measured by the editor at save time. It is the box that bounds-validation and the
server renderer both use. The server never re-derives the box from font metrics (see §3 for
why this kills most browser/server drift).

## 2. Font strategy

### Whitelist, bundled, open-licensed only

- A fixed whitelist of 4–6 fonts, each under SIL OFL 1.1 or Apache 2.0 (both permit
  bundling + commercial use + embedding). Shipped set:

  | Key | Family | Style niche | License |
  |---|---|---|---|
  | `inter` | Inter | neutral sans | OFL 1.1 |
  | `oswald` | Oswald | condensed display | OFL 1.1 |
  | `playfair` | Playfair Display | serif display | OFL 1.1 |
  | `roboto-slab` | Roboto Slab | slab serif | Apache 2.0 |
  | `caveat` | Caveat | handwriting | OFL 1.1 |

- No arbitrary uploaded fonts. No system fonts. No Google Fonts CDN at render time (the
  server must work offline; the editor must show exactly the file the server will use).

### Single source of truth

- `packages/shared/src/fonts.ts` exports the whitelist metadata (key, display name, file
  name, license): pure data, keeps shared dependency-free.
- Font binaries (one variable TTF per family) live once in the repo at
  `packages/renderer/fonts/<key>/`, each with its license file (`OFL.txt` or
  `LICENSE.txt` for Apache) checked in next to it.
- `apps/web` loads the same TTFs via the `FontFace` API from the API's
  `GET /fonts/:key/file` endpoint and preloads all whitelisted fonts before the
  canvas mounts, so Fabric never measures with a fallback font.
- `packages/renderer` resolves `fontFamily` key → TTF path internally. The API passes only
  the whitelist key; the renderer owns the file mapping (mirrors the existing rule that
  `StorageService` is the only thing touching the storage layout — the renderer is the only
  thing touching font files).

### Licensing risk — stated clearly

- **Allowed licenses: SIL OFL 1.1 and Apache 2.0, nothing else.** OFL permits bundling,
  embedding, and commercial use, but **forbids selling the fonts by themselves** and
  requires the license file to travel with the font. Apache 2.0 permits all of the above
  and requires the same license-file attribution. Keeping the license file per family
  in-repo satisfies both.
- Risk to avoid: swapping in a font with a desktop-only or web-only license (many foundry
  fonts forbid server-side rasterization). Rule: any font added to the whitelist must be
  OFL or Apache-2.0, verified at the source (Google Fonts repo carries license metadata).
- Caveat for later commercial use: "free for personal use" fonts (common in handwriting
  styles) are NOT acceptable. Document this in the whitelist file header.

## 3. Rendering strategy

### Editor: Fabric text object

- Fabric v6 `Textbox` is the user's stated preference; the wrap-behavior decision below
  affects which class we actually instantiate (`Textbox` vs `IText`).
- **Decision needed — auto-wrap is the single biggest parity risk.** `Textbox` wraps lines
  automatically at its width using the *browser's* text measurement. The server would have
  to reproduce the exact same wrap points with *Pango's* measurement; a 1px metric difference
  moves a word to the next line and the render visibly diverges.
- **Recommendation for v1.5: no auto-wrap.** Use `IText` (or `Textbox` with width synced to
  content): lines break only on explicit `\n` (Enter key). Line breaks become part of the
  stored `text`, so browser and server agree on line structure by construction. Auto-wrap
  can ship later as v1.5.x once the no-wrap pipeline is proven.
- Interaction rules:
  - Corner handles = uniform scale only; middle handles disabled on text objects.
  - On save, uniform scale is **baked into `fontSize`** (`fontSize * scaleY`, then scale
    reset to 1) and `width`/`height` re-measured. The stored object never carries scale.
  - Double-click = Fabric inline editing (free with IText/Textbox).
  - Existing clamp-to-print-area handler applies unchanged (it operates on generic object
    geometry).

### Server: sharp text input (Pango), not hand-built SVG

Primary approach — `sharp`'s `text` input source:

```ts
sharp({
  text: {
    text: obj.text,            // PLAIN text — Pango markup disabled
    font: family,              // e.g. 'Inter'
    fontfile: resolvedTtfPath, // bundled file, from whitelist key
    rgba: true,
    align: obj.align,          // 'left' | 'centre' | 'right'
    dpi: 72,                   // 72 dpi → 1pt = 1px, so fontSize maps 1:1 to px
  },
})
```

Why Pango over an SVG `<text>` composite:

- No XML string assembly → no SVG injection surface at all (user text never enters markup).
- Pango + HarfBuzz do real shaping (kerning, ligatures, and correct Arabic shaping if RTL
  is added later). librsvg text support is comparatively weak.
- Color is applied by tinting the rasterized alpha layer (composite the rgba text mask over
  a flat color, or `tint`), so the `#RRGGBB` value also never enters any markup.

### Keeping measurement "close enough" — render-then-fit

Exact metric parity between browser canvas text and Pango is not achievable (different
shapers, hinting, rounding). Instead of chasing it:

1. Editor measures the text box and stores `width`/`height` in the document (the box the
   user actually saw and validated against).
2. Server renders the text layer at its **natural Pango size** (same font file, same
   fontSize, same line breaks).
3. Server then **resizes that layer to exactly the stored `width` × `height`** (`fit: 'fill'`),
   then rotates and composites — identical to the existing image-layer pipeline from there.

Consequence: the rendered text always occupies exactly the box that was validated. A metric
difference between browser and Pango shows up as a sub-percent glyph stretch instead of an
overflow or a moved wrap point. With the same font file on both sides the divergence is
typically 1–3% — invisible at mockup scale.

### Renderer interface change

`RenderObject` becomes a union mirroring the contract:

```ts
type RenderObject =
  | { type: 'image'; imagePath: string; x; y; width; height; rotation }
  | { type: 'text'; text: string; fontFamily: FontFamilyKey; fontSize: number;
      color: string; align: 'left' | 'center' | 'right'; x; y; width; height; rotation };
```

`prepareObjectLayer` gains a text branch: Pango raster → tint to `color` → resize to
`width`×`height` → rotate (existing transparent-background rotate) → center-anchored
placement (existing math, unchanged).

### Known limitations (documented, accepted for v1.5)

- Glyph stretch up to a few percent from render-then-fit (see above).
- No auto-wrap; explicit line breaks only.
- No letter-spacing, line-height, stroke/outline, shadow, curved text.
- One font style per object (no per-character styling, no bold/italic variants in v1).
- RTL/Arabic not officially supported in v1.5 (see Risks).
- **Spike required before implementation**: verify sharp's text input works on the Windows
  dev machine (libvips text needs fontconfig; prebuilt binaries usually include it, but this
  must be proven first). Fallbacks if it fails, in order: (a) SVG composite with XML-escaped
  text + strict escaping rules, (b) `canvaskit-wasm` (Skia) for fully deterministic
  cross-platform text. The spike is task #1 of the implementation phase.

## 4. Validation plan

All rules live in `packages/shared` (pure, both sides run them) plus class-validator DTOs at
the API boundary. Server stays the authority.

### Field rules (text objects)

| Field | Rule |
|---|---|
| `text` | string, 1–300 chars after trim, must contain non-whitespace, max 8 lines (`\n` count ≤ 7), no control chars except `\n` (strip `\r`) |
| `fontFamily` | must be a key in the shared font whitelist (enum check) |
| `fontSize` | finite number, 12 ≤ fontSize ≤ 500 (canvas px) |
| `color` | regex `^#[0-9a-fA-F]{6}$` — exactly one format, nothing else |
| `align` | enum `left` / `center` / `right` |
| `x, y, width, height, rotation` | identical rules to image objects (finite, positive size, rotation −360..360) |

Color: strict hex regex instead of a server-enforced palette. The palette is a UI concern
(curated swatches), but any `#RRGGBB` is printable and safe; restricting server-side to a
palette would break saved designs every time the palette is tweaked.

### Geometry rules

- Same rotated-corner bounds check as images: `isObjectInsideRect` on the stored
  `width`/`height` box — **rotated bounds are already covered** by the existing corner math,
  no new geometry code needed.
- `validateDesignObjects` extends per-type: base geometry checks run for every object, text
  field checks run for `type === 'text'`.
- Defense in depth: the renderer re-validates bounds (already does) and the render-then-fit
  step guarantees text physically cannot draw outside its validated box even if metrics lie.

### DTO layer (`create-design.dto.ts`)

class-transformer discriminated union:

```ts
@Type(() => DesignObjectBaseDto, {
  discriminator: {
    property: 'type',
    subTypes: [
      { value: ImageObjectDto, name: 'image' },
      { value: TextObjectDto, name: 'text' },
    ],
  },
  keepDiscriminatorProperty: true,
})
```

- Back-compat at the boundary: an incoming object **without** `type` but with `assetId` is
  accepted as an image (transform step defaults it) so an un-upgraded client keeps working.
- `whitelist + forbidNonWhitelisted` stays on; the subtypes whitelist their own fields, so a
  text payload smuggling `assetId` (or vice versa) is rejected.

### Quality warnings (DPI)

Text is vector: it has no source bitmap, so DPI math does not apply. `collectQualityWarnings`
and `worstQualityLevelOf` filter to `type === 'image'` objects explicitly. A text-only design
has `worstQualityLevel: null` ("nothing evaluable"), which the library UI already handles.

## 5. API impact

| Endpoint | Change |
|---|---|
| `POST /designs` | accepts text objects via the DTO union; `validateAndBuildDocument` maps per type; `assertAssetsExist` runs only over image objects |
| `PUT /designs/:id` | same as create (shared validation chain) |
| `POST /designs/:id/render` | builds the `RenderObject` union; resolves asset paths for images, passes whitelist key + text fields for text |
| `GET /designs/:id` | unchanged shape; `design` now may contain text objects; `qualityWarnings` covers images only |
| `GET /designs` (library) | `objectCount` unchanged (total). **Additive**: `imageCount` + `textCount` on `DesignPlacementSummaryDto` so the library can show "2 images · 1 text". Additive fields, nothing breaks |

No breaking changes for existing image designs:

- Stored docs without `type` normalize to image at read time.
- Old clients sending objects without `type` still validate (DTO default).
- All existing endpoints keep their response shapes; new fields are additive.

## 6. UI plan (editor)

Scope: minimal, consistent with the existing toolbar/panel style. No new design system work.

1. **Add Text button** in the toolbar next to the upload control. Inserts a text object
   centered in the active print area: `"Your text"`, default font (`inter`), 48px, black
   `#1a1a1a`, align center, `printAreaKey` = active area. Selects it immediately.
2. **Text panel** — shown when the selection is a text object (same slot as the current
   image-selection info):
   - content edit: double-click inline edit on canvas is primary; panel shows a hint, not a
     duplicate textarea (one editing surface, no sync bugs)
   - font select: dropdown over the whitelist, each option rendered in its own face
   - color: row of curated swatches + native `<input type="color">` clamped to hex
   - size: numeric input + −/+ steppers, clamped 12–500
   - delete: button in panel (Delete/Backspace key support if the existing canvas handlers
     make it free)
3. **Transform behavior**: middle scale handles hidden, corner scale = uniform, rotation
   handle unchanged. Existing clamp/fit-to-print-area handlers apply as-is.
4. **Serialization** (`collectPlacements`): branch on object kind — Fabric text objects carry
   `printAreaKey` exactly like images do today; scale bakes into `fontSize` on save.
5. **Reopen** (`initialDesign` load): text objects reconstruct as Fabric text instances from
   stored fields; fonts are preloaded before canvas mount so measurement is correct on
   first paint.

- normalize: object without `type` → image; v1 doc with typeless objects → v2 typed

  chars, font key, size bounds, color regex, align enum)

- text PNG output: render a known string on a flat base → assert output dims, assert
  non-transparent pixels concentrated inside the expected box, assert pixel color matches
  `color`

  the box are untouched)
- rotation: rotated text stays inside print area; rotated bounds composite correctly
- unknown font key → typed error (no fontconfig fallback silently kicking in)
- mixed objects: image + text composite in document order

- each invalid text field → 400 with the field-specific message
- text outside print area (incl. rotated) → 400

- mixed image + text design: save + render
- regression: existing image-only fixtures still save/render unchanged

- move/resize/rotate text, save → success toast

## 8. Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Browser vs server text metric mismatch | High (core feature quality) | Same font files both sides; no auto-wrap (explicit `\n` only); render-then-fit so divergence = sub-percent stretch, never overflow/rewrap. Visual spot-check in review |
| sharp/libvips text unsupported on Windows dev box | High (blocks approach) | Spike is task #1. Fallbacks: escaped-SVG composite, then canvaskit-wasm |
| RTL / Arabic | Medium | Out of scope v1.5. Pango+HarfBuzz shape Arabic correctly server-side, and browsers do too, but bidi alignment + mixed-direction parity is untested; whitelist has no Arabic-script font yet (Noto Naskh Arabic is OFL, an easy later add). Document as unsupported, do not block typing |
| Font licensing | Medium (legal) | OFL/Apache only, license file checked in per family, rule documented in whitelist header. No "free for personal use" fonts ever |
| SVG/markup injection via text or color | High if SVG fallback used | Primary path (Pango plain-text) has no markup surface. Color via strict regex, font via enum. If SVG fallback becomes necessary: XML-escape text, same regex/enum rules, no user value ever concatenated unescaped |
| Long text / layout overflow | Low | 300-char + 8-line caps; bounds validation on the measured box; render-then-fit physically clamps to the box |
| Fabric inline-edit vs clamp handler fighting (box grows past area edge while typing) | Medium (UX) | Clamp on `editing:exited` rather than every keystroke; if the grown box can't fit, shrink fontSize or revert — decide in implementation, test explicitly |
| Color input allowing non-hex (named colors) sneaking through UI | Low | Single normalization point in editor state; server regex rejects regardless |

## Implementation results (2026-06-06)

### Spike: PASS

sharp's Pango text input works on the Windows dev machine with the prebuilt libvips:
plain-text rendering, `fontfile` loading of bundled TTFs, fractional point sizes
(`dpi: 72` so 1pt = 1px), multi-line via `\n`, and `align` all verified. No SVG or
canvaskit fallback needed. CI (ubuntu) is covered by the committed renderer tests,
which render through the same path on every run.

### Deviations from the plan

- **DTO: single class + `@ValidateIf`, not class-transformer subtype discrimination.**
  One `DesignObjectDto` with conditional validators is simpler to debug than the
  discriminator machinery, and kind purity is enforced by the shared authority
  validation anyway. A typeless payload with `assetId` validates as an image, so
  pre-v1.5 clients keep working.
- **Purity checks compare against `undefined`, not the `in` operator.** With
  `target: ES2022` (`useDefineForClassFields`), every declared DTO field exists as an
  own `undefined` property on the instance, so `'text' in obj` was true for every
  object and rejected all image saves. Caught by the API e2e suite on first run.
- **Fonts are streamed by the API (`GET /fonts/:key/file`), not bundled into the web
  app.** One binary per family in `packages/renderer/fonts/<key>/`; the editor loads
  them via the `FontFace` API from the same endpoint, so browser and server provably
  use the same file. The renderer owns the key→file mapping (`resolveFont`); the API
  and web pass whitelist keys only.
- **Roboto Slab is Apache-2.0**, not OFL (it lives under `apache/` in the google/fonts
  repo). The whitelist rule was widened to "OFL-1.1 or Apache-2.0"; the license file
  is checked in next to the binary like the others.
- **Text color is applied by compositing** the Pango glyph alpha over a flat color
  (`dest-in` blend), so neither the text nor the color ever enters a markup string.
- **`clampTextScale` in the editor** keeps the effective font size
  (`fontSize * scale`) inside the 12..500 contract bounds during corner scaling, so a
  scaled text object can never serialize to a size the server rejects.
- **Editor uses `IText`** (no auto-wrap, explicit `\n` only), as recommended in §3.
  Uniform corner scaling bakes into `fontSize` at serialize time; middle handles are
  disabled.

### Confirmed limitations (unchanged from §3)

- No auto-wrap; explicit line breaks only. No letter-spacing, stroke, shadow, curved
  text, or per-character styling. RTL/Arabic not officially supported.
- Render-then-fit means up to a few percent glyph stretch when browser and Pango
  metrics disagree; invisible at mockup scale in manual checks.
